# External routing dataset review

**Reviewed:** 6 September 2026

**Decision:** No external dataset has been imported into the production evidence
set yet. The strongest public candidates are useful for research, but none currently
meets all three requirements for this system without additional legal and technical
work: explicit commercial data rights, independence from the existing synthetic
generator, and outcomes that transfer to the deployed GPT-5.6 model family and our
intended workload.

## Acceptance criteria

An external dataset can count toward the production generalisation gate only if:

- its prompts and labels were not produced by the current datagen pipeline;
- the exact dataset revision, source URL, license, and SHA-256 are recorded;
- commercial use and retention in our environment have been approved;
- normalized prompts are deduplicated against every train, validation, and test row;
- at least 1,000 unique held-out examples remain after deduplication;
- labels come from independent human review or model-response outcomes, not a new
  copy of our existing complexity rubric generated by an LLM;
- the set covers the intended use cases and multi-turn distribution; and
- it remains frozen and is never used for model or threshold selection.

## Candidates reviewed

### RouterBench

[RouterBench](https://github.com/withmartian/routerbench) publishes an MIT-licensed
evaluation framework and links to a 1.47 GB
[Hugging Face dataset](https://huggingface.co/datasets/withmartian/routerbench) with
more than 30,000 prompts, responses from 11 models, cost estimates, and correctness
scores. This is attractive because it provides response outcomes rather than
subjective difficulty labels.

It is not approved for ingestion. The dataset card does not declare a data license,
and the model pool predates the deployed GPT-5.6 family. The code license does not by
itself establish rights to the bundled benchmark prompts or model outputs. If legal
review clears the underlying data, RouterBench could become an out-of-distribution
diagnostic, but its old-model outcomes must not be represented as current workload
quality.

### RouteLLM and Chatbot Arena preferences

[RouteLLM](https://github.com/lm-sys/RouteLLM) is Apache-2.0-licensed code and is a
strong algorithmic reference for learning strong-versus-weak routing from preference
data. Its released routers were trained for GPT-4 versus Mixtral, and its own
documentation recommends calibrating thresholds on incoming-query distributions.

This makes RouteLLM useful as a future challenger implementation, not a drop-in
external label source for our three current roles. Any use of the linked Chatbot
Arena data also needs a separate review of that dataset's terms and privacy model.

### LLMRouterBench

[LLMRouterBench](https://github.com/ynulihao/LLMRouterBench) is the most technically
relevant candidate reviewed. It reports more than 400,000 instances across 21+
datasets and 33 models, with standardized queries, predictions, scores, token usage,
and cost, plus in-distribution and out-of-distribution evaluation support.

It is not approved for ingestion because the repository and linked Hugging Face
bundle do not currently present a clear top-level data license, and the bundle
combines many upstream benchmarks with their own terms. It also evaluates GPT-5-era
models rather than the exact deployed GPT-5.6 targets. Subject to legal approval, a
small source-compatible subset could be used for external diagnostic testing and
oracle-regret analysis.

### Switchyard Harbor benchmark

The current
[Switchyard benchmark harness](https://github.com/NVIDIA-NeMo/Switchyard/blob/main/benchmark/README.md)
supports the same Harbor task set in direct-upstream and Switchyard-routed modes. It
is well suited to end-to-end agentic coding and gateway-overhead tests because both
arms use the same task images and agent versions.

This should be added as a separate system benchmark after provider spend, execution
environment, and benchmark terms are approved. It covers an important coding slice,
but it is not a representative replacement for general Q&A, ordinary reasoning, or
the organisation's own production requests.

## Recommended next step

Use two independent tracks:

1. Obtain legal approval for a license-compatible subset of LLMRouterBench or
   RouterBench, store it outside the public repository, and use it only as a frozen
   out-of-distribution diagnostic after strict deduplication.
2. Build the actual release benchmark from privacy-reviewed intended workloads and
   run all three current model roles on every case. Use the public benchmark only to
   widen failure discovery; use the workload benchmark for production quality,
   latency, and cost approval.

The existing 455-row multi-turn slice remains correctly classified as a related
synthetic diagnostic. Generating more examples from that same process would not make
the generalisation gate independent.
